# ADR-008. Город как ядро: проектирование с проверкой, четыре уровня детализации

Статус: принято 14.11.2026.

## Контекст
Заказчик определил замысел платформы: ученик входит и проектирует водную инфраструктуру города, детализация растёт методом последовательных приближений — от блоков и труб до формул, уклонов, процессов и нормативных документов. Модули остаются как элементы города, в которые можно углубиться. Всё бесплатно: статьи, конструкторы, уроки, геймификация.

## Решение
1. **Не симуляция времени, а проектирование с проверкой.** Ход — «спроектировал → проверил по нормам и ТЭП → улучшил». Ядра считают по-настоящему на любом уровне; нет игрового времени, экономической симуляции, роста населения, 3D.
2. **Город — проект проектов.** `city { название, сценарий, население и застройка, водный объект (категория А–Г), план (ADR-009), объекты: [водозабор, водоподготовка, сеть водоснабжения, застройка, водоотводящая сеть, очистные, выпуск] }`; каждый объект — проект модуля по ADR-005. Связь объектов — баланс воды и загрязнений по городу: потребление → сеть → канализация → очистка → выпуск → норматив реки; стоимость — по НЦС.
3. **Контракт ядра.** Каждое расчётное ядро экспортирует `calc(вход) → { выход, стоимость, энергия, проверки[], логика[] }`, где `проверки` — список `{ норма, пункт, выполнено, значение, предел }`, `логика` — шаги расчёта с формулой, подстановкой, источником и типом (норма / методика / допущение), как в `sewercalc.js`. Город вызывает ядра по контракту и собирает общий баланс. Новое ядро — модель потребления: жители, промзона, неучтённые расходы → расходы по суткам и часам (СП 31 табл. 1, СП 32 табл. Г.1).
4. **Уровни детализации — свойство экрана, не расчёта.**
   - 0 — блоки на карте, баланс, река чистая/грязная, стоимость; всё по умолчаниям из норм.
   - 1 — мощности, диаметры, категория реки, расходы на жителя; таблицы СП видны.
   - 2 — конструкторы модулей, как сейчас; результат возвращается в город.
   - 3 — процессы, формулы, пункты норм, статьи базы знаний, полные тексты актов.
   Переход вниз — по потребности (норматив не выполнен — опускайся), не по принуждению. Уровни открываются выполненными городами; «шедевр» гильдии — город на уровне 3, проверенный экспертом.
5. **Сценарии — контент.** `content/scenarios/<id>.md`: исходные данные города (план, население, река, ограничения) и критерии успеха. Пишут кураторы и преподаватели без кода. Первые: посёлок 5 000 на реке категории В; город 100 000 с промпредприятием; реконструкция станции под ПП 1430; сжимающийся моногород.

## Последствия
- Главная страница становится картой города (ADR-009); модули открываются из неё.
- Этап 1 получает две сессии: контракт ядра + модель потребления. Уровень 0 города — первая работа этапа 2 и предмет практикума.
- Чего не делаем до этапа 3: география за пределами плана сценария, время, экономика города, сетевая игра, рейтинги.
